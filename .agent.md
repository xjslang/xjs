## Parser Philosophy: Syntax vs Semantics

The parser is **intentionally permissive** and focuses solely on **syntactic correctness**, not semantic validity. This means:

- ✅ The parser accepts any syntactically valid JavaScript construct
- ❌ The parser does NOT validate semantic correctness

**Examples of syntactically valid but semantically incorrect code:**
- `a + b = 100` (cannot assign to expression)
- `for (100 in rows)` (cannot assign to literal)
- `const x = y = z` (undefined variables)

**Rationale:**
1. Keeps parser code simple and maintainable
2. Semantic validation is better handled by specialized tools (ESLint, TypeScript, etc.)
3. Allows flexibility for code transformation and analysis tools
4. Follows standard compiler architecture (separate parsing and semantic analysis phases)

**Example:**

```go
func Test(t *testing.T) {
	// semantically incorrect
	input := `a + b = 100`

	// the code above does not generate errors, because it is understood
	// that writing semantically correct code is the user's responsibility.
	result, err := xjs.Parse([]byte(input))
	require.NoError(t, err)
}
```
